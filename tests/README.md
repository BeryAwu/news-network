# Test approach

The current Vitest suite has 20 tests in `core.test.ts`. It covers selected pure/core behaviors, including AI configuration and structured-output/evidence validation, hostname/IP and slug handling, approval-time evidence snapshots, and asset-license provenance. It is not a comprehensive integration or security suite: it does not exercise every route, authorization boundary, database race, publishing worker, or real Cloudinary upload.

The local application has had smoke checks for dashboard pages and selected API behaviors; see `IMPLEMENTATION_STATUS.md` for the latest recorded scope. Before production, add isolated database/route tests for cross-tenant authorization, editorial transitions, upload/finalize, publish/retry concurrency, and public tenant rendering. Separately test a real Cloudinary upload with a rights-cleared image and scheduled publishing with a real Redis-compatible service and worker. Do not treat mocks or local smoke checks as proof of those external integrations.
